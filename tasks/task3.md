# Этап 3. Интеграция с Prometheus и Grafana

## 📌 Бизнес-ценность
Визуализация метрик в реальном времени, возможность строить графики и дашборды для мониторинга состояния сервера без необходимости подключаться к серверу по SSH.

---

## 🎯 Функциональные требования

### 1. Экспорт метрик в формате Prometheus

- Добавить поддержку формата Prometheus для эндпоинта `/metrics`.
- Использовать пакет `github.com/prometheus/client_golang` для создания и регистрации метрик:
    - `cpu_percent` (gauge) – загрузка CPU в процентах.
    - `mem_used_mb` (gauge) – используемая память в МБ.
    - `mem_total_mb` (gauge) – общая память в МБ.
    - `disk_used_gb` (gauge) – используемое дисковое пространство в ГБ.
    - `disk_total_gb` (gauge) – общее дисковое пространство в ГБ.
    - `alerts_active_total` (gauge) – количество активных (не resolved) алертов.
    - `alerts_total` (counter) – общее количество созданных алертов (за время работы сервиса).
- Метрики должны обновляться при каждом сборе (каждые 5 секунд).
- **Совместимость с существующим API:**
    - Эндпоинт `/metrics` должен поддерживать два формата:
        - По умолчанию (`Accept: application/json`) – отдавать JSON (как на Этапе 1).
        - Если `Accept: text/plain` или `Accept: application/openmetrics-text` – отдавать текст в формате Prometheus.
    - Это обеспечит обратную совместимость с существующими интеграциями.

### 2. Запуск Prometheus

- Создать файл `prometheus.yml` с конфигурацией для сбора метрик с нашего сервиса.
- Добавить сервис `prometheus` в `docker-compose.yml`.
- Prometheus должен иметь доступ к сервису (в compose-сети использовать имя сервиса или `host.docker.internal`).

**Пример конфигурации `prometheus.yml`:**
```yaml
global:
  scrape_interval: 5s
  evaluation_interval: 5s

scrape_configs:
  - job_name: 'server_watch'
    static_configs:
      - targets: ['agent:8080']  # или host.docker.internal:8080 при локальной разработке
```
 
### 3. Запуск Grafana
- Добавить сервис grafana в docker-compose.yml.
- Предоставить дашборд (JSON-файл) с графиками:
  - Загрузка CPU (%).
  - Использование памяти (used/total в МБ).
  - Использование диска (used/total в ГБ).
  - Количество активных алертов.
  - Общее количество алертов.

- Источник данных должен быть автоматически настроен на Prometheus (через provisioning).
- Дашборд должен быть доступен по порту 3000 (логин/пароль по умолчанию: admin/admin).

### 4. Логирование
- Все логи перевести на slog с уровнями:
    - INFO – запуск/остановка сервиса, сбор метрик, запросы к API.
    - WARN – превышение порогов (но до создания алерта).
    - ERROR – ошибки чтения /proc, проблемы с БД, сбои в работе.
- Логи выводятся в stdout в формате JSON (для последующей интеграции с ELK/Loki).

### Нефункциональные требования
- Метрики должны обновляться в Prometheus с той же частотой, что и сбор (5 сек).
- Время ответа на /metrics (Prometheus-формат) < 50 мс.
- Дашборд Grafana должен загружаться < 5 секунд.
- Prometheus должен корректно обрабатывать временные недоступности сервиса (retry).

### Критерии приёмки
- curl http://localhost:8080/metrics возвращает JSON с метриками (по умолчанию).

- curl -H "Accept: text/plain" http://localhost:8080/metrics возвращает текст в формате Prometheus.

- docker-compose up запускает сервис, Prometheus и Grafana без ошибок.

- Prometheus видит цель agent:8080 и успешно собирает метрики (проверить в UI Prometheus: http://localhost:9090/targets).

- В Grafana после импорта дашборда отображаются все графики с данными.

- Логи выводятся через slog в структурированном виде.

### Технологический стек (дополнения к Этапу 3)
- github.com/prometheus/client_golang – для экспорта метрик.
- github.com/prometheus/client_golang/promhttp – для HTTP-хендлера.
- Docker / Docker Compose – для запуска Prometheus и Grafana.
- log/slog – для структурированного логирования.

### Взаимодействие с предыдущими этапами
- Данные для метрик берутся из того же источника, что и на Этапе 1 и 2 (сбор из /proc и syscall).
- SQLite остаётся для долгосрочного хранения, но не используется для восстановления состояния Prometheus-метрик.
- /health остаётся без изменений.

### Дополнительные замечания
- При разработке локально (без Docker) можно запустить Prometheus и Grafana вручную, но в рамках этапа требуется автоматизация через docker-compose.yml.
- Для удобства можно добавить Makefile с командами make up и make down для запуска/остановки стека.
