Этап 1. Сервис с HTTP API

Бизнес‑ценность: Мониторинг интегрируется в существующие системы сбора (Prometheus, Grafana) и позволяет удалённо получать метрики.

Функциональные требования:

Программа становится долгоживущим сервисом, который:

Собирает метрики каждые 5 секунд в фоновой горутине.

Кэширует последние значения в памяти.

HTTP‑сервер слушает порт 8080.

Доступны следующие эндпоинты:


| Метод | Путь | Описание | Параметры | Ответ | Коды ошибок |
|-------|------|----------|-----------|-------|-------------|
| GET | `/metrics` | Получить текущие метрики в JSON | Нет | `{"cpu_percent": 12.5, "mem_percent": 45.2, "mem_used_mb": 3840, "mem_total_mb": 8192, "disk_percent": 60.1, "disk_used_gb": 45, "disk_total_gb": 75}` | 200, 500 |
| GET | `/health` | Проверка работоспособности | Нет | `{"status":"ok"}` | 200, 503 |

Сервис корректно завершается по сигналам SIGTERM/SIGINT (graceful shutdown).
Нефункциональные требования:

Время ответа на /metrics < 10 мс (без учёта сетевой задержки).

Потребление памяти не более 50 МБ.
Критерии приёмки:

После запуска go run main.go сервис доступен на http://localhost:8080/health.

curl http://localhost:8080/metrics возвращает JSON с актуальными данными.

При получении SIGTERM завершается не дольше 2 секунд
